# college-finance

Read [the project contract](../../../docs/DATA-API.md) for the active task. Resolve project paths relative to the repository root.

Calculate balances in deterministic server code with integer paise. Show expected scholarship separately from settled allocations; represent pending, partial, reversed and excess payments correctly. Every status includes source and observation time.

Scholarship explanation must distinguish known facts, possible causes and missing evidence. Use the approved department directory; draft complaint text from authorized context. Submission is an explicit domain command with dedup key, audit event and receipt.

Keep complaint resolved separate from verified_closed and scholarship credited. Staff assertion or model confidence alone cannot post money. Reminders recheck current balance/case state and preferences at send time. Penalties/attendance consequences need actual college policy, not assumptions.

Test blueprint amounts, partial credit, duplicate imports, stale records, duplicate complaint submit and false closure. Deliver one complete investigation-to-tracking flow; external email remains disabled until its integration and authorization exist.
