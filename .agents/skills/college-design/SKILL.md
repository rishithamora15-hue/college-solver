# college-design

Read [the project contract](../../../docs/DESIGN.md) for the active task. Resolve project paths relative to the repository root.

Start from the active student or staff journey and its persisted state. Reuse the common shell, form patterns and status vocabulary. Expose four connected modules through one identity and consistent navigation.

Render loading, empty, stale, denied, failed and queued states. Show sources and observation times for financial/AI results. Complaint submission needs an editable review and durable receipt. Resume suggestions show original text, proposed change, reason and supporting facts.

Keep real student data out of screenshots. Verify keyboard completion, meaningful labels/focus, mobile width, long content, 200% zoom and screen-reader status announcements. Never encode status only in color or let hidden navigation stand in for authorization.

Deliver the implemented screen and observed checks. Stop at the ticket; avoid adding a new design system or decorative dashboard content without a real data source.
